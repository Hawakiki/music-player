# 뮤직 플레이어 아이디어

2026-11-05 대화 정리. 브라우저 지원 범위는 대화 당시 지식 기준이라 구현할 때 다시 확인한다.

## 목표

- 사용자가 지정한 로컬 음악 폴더를 브라우저에서 재생하는 웹 플레이어
- 백엔드 없는 정적 사이트, GitHub Pages(github.io) 배포
- 지정한 폴더(여러 개)를 기억하고, 다시 오면 자동으로 연결
- 설정, 재생목록 등은 브라우저에 저장

## 결정한 것

| 항목 | 결정 |
|---|---|
| 스택 | Vite + React + TypeScript, Tailwind CSS, shadcn/ui |
| 라우팅 | `HashRouter` (GitHub Pages에서 새로고침 404 방지) |
| 빌드 경로 | `base: './'` (저장소 이름에 묶이지 않게) |
| UI 디자인 | frontend-design 스킬을 로드하고 작업 |
| 폴더 선택 | `showDirectoryPicker()` 기본, 미지원 브라우저는 `webkitdirectory`로 대체 |
| 파일 추가 | 드래그 앤 드롭은 항상 켜 둠 |
| 폴더 핸들, 재생목록, 메타데이터 캐시 | IndexedDB |
| 볼륨, 테마, 셔플/반복, 마지막 재생 위치 | localStorage |
| 데이터 보호 | `navigator.storage.persist()` 요청 |
| 재생목록 백업 | JSON 내보내기/가져오기 |
| 자동 재연결 범위 | Chrome/Edge만. Firefox/Safari는 매번 폴더를 다시 선택 |
| 쿠키 | 사용 안 함 (서버가 없음) |

## 디자인 방향

- 장난스러운 콘셉트가 아니라 전문적인 느낌의 툴. 다만 투박하거나 전문 용어를 쏟아내지 않는다 (Poweramp, UAPP 느낌).
- 화면 구조는 Spotify, Apple Music, 소니 DAP(W.뮤직)를 참고한다.
- 강한 대비, 형광색, 장식은 뺀다. 색은 무채색 + 포인트 하나로 통일하고, 나머지 색은 앨범 아트에서 나오게 둔다.
- 테마는 설정에서 자동/블랙/화이트로 고른다.
- 참고 앱에서 가져올 것: 포맷 한 줄 표시, 10밴드 EQ + 프리앰프, 파형 탐색바, 대기열, 초성/A–Z 인덱스.
- 브라우저 한계: 재생이 OS 오디오를 거치므로 UAPP의 비트퍼펙트, USB DAC 직접 출력은 불가능하다.

## 디자인 계획

시안은 `docs/drafts/`에 있다. 세 시안을 합쳐서 쓴다.

| 전체 화면 재생 | 큰 앨범 아트, 파형 탐색바, 대기열/이퀄라이저/곡 정보 탭 | B |

### 테마

- 설정 > 화면 > 테마에서 자동/블랙/화이트를 고른다. 기본값은 자동이다.
- 자동은 `prefers-color-scheme`을 따르고, 앱이 켜진 동안 바뀌어도 `matchMedia`의 change 이벤트로 바로 반영한다.
- 선택 값은 localStorage의 `music-player:theme`에 저장한다.
- 새로고침 때 깜빡이지 않도록 `index.html`의 인라인 스크립트에서 React보다 먼저 적용한다.
- shadcn 기준에 맞춰 `html`의 `dark` 클래스로 전환한다.

### 구현 순서

1. 테마, 토큰, 앱 틀
2. 폴더 연결, 재연결, 파일 스캔
3. 재생, 대기열, 플레이어 막대
4. 태그/앨범 아트 읽기, 라이브러리 화면, 즐겨찾기, 검색
5. 전체 화면 재생, 이퀄라이저, 파형, 재생목록 만들기와 내보내기/가져오기

## 태그와 라이브러리

- 태그는 Web Worker에서 `music-metadata`로 읽고 IndexedDB에 캐시한다. 다음 방문부터는 크기나 수정 시각이 바뀐 파일만 다시 읽는다.
- 라이브러리에는 태그를 읽은 곡만 올린다. 파일 이름으로 묶었다가 태그가 도착해서 화면이 뒤섞이는 일을 막는다.
- 앨범 묶기: 앨범 아티스트 태그를 우선한다. 없으면 같은 폴더에 아티스트가 여럿인 앨범은 `여러 아티스트`로 묶고, 앨범 태그가 없으면 폴더 이름을 앨범으로 쓴다.
- 앨범 아트: 태그의 이미지, 없으면 같은 폴더나 바로 위 폴더의 `cover`, `folder`, `front`, `album`, `albumart` 이미지를 쓴다. 384px 정사각형 썸네일로 줄여서 해시로 한 번만 저장한다.
- 안 쓰는 표지는 태그 읽기가 끝난 뒤에만 정리한다. 읽는 중에 지우면 방금 저장한 표지가 사라진다.

## 이퀄라이저와 파형

- 이퀄라이저를 끈 사람은 `<audio>`가 직접 출력한다. 켜면 `프리앰프 → 10밴드 peaking 필터 → 출력` 그래프를 탄다.
- 한 번 그래프로 연결한 `<audio>`는 되돌릴 수 없다. 끄면 필터만 건너뛰고, 그래프는 새로고침 전까지 남는다.
- 설정이 켜진 채로 시작하면 재생을 누른 뒤에 그래프를 만든다. 자동 재생 정책 때문이다.
- 파형은 전체 화면을 열었을 때만 계산한다. 8kHz로 풀어서 메모리를 아끼고, 결과는 IndexedDB에 캐시한다.
- 전체 화면 표지는 썸네일 대신 원본을 파일에서 읽는다.

## 음향

- 들으면서 비교하는 값은 전체 화면의 음향 탭, 한 번 정하면 안 건드리는 음량 평준화와 리미터는 설정에 둔다.
- 신호 순서: 음량 평준화 → 고역 복원 → 프리앰프 → EQ → 저음/고음 → 진공관 → 저역 위상 → 바이닐 → 스테레오 폭/모노 → 크로스피드 → 밸런스 → 리미터.
- 진공관 곡선은 4배 오버샘플링으로 약 4ms 늦다. 원음도 직선 곡선을 지나게 해서 시간을 맞춘다. 안 맞추면 섞을 때 고역이 패인다.
- 진공관은 곡선이 더한 왜곡만 뽑아서 120Hz 아래를 없앤 뒤 원음에 더한다. 양은 더하는 왜곡의 크기로 정한다. 곡선 뒤에서 저역을 복원하는 방식은 곡에 없던 저역 찌꺼기까지 키워서 쓰면 안 된다.
- 곡선에 넣을 때는 저역을 18dB 줄인다. 안 그러면 큰 베이스가 곡선을 밀어서 보컬까지 찌그러진다. 둘 다 사인파 하나로는 안 드러나고 실제 곡이나 두 음 시험에서 드러난다.
- 앰프 모드는 실제 앰프 재현이 아니라 성격을 본뜬 것이다. 트라이오드는 2차 배음에 300Hz +2dB, 7kHz -2dB. 울트라리니어는 왜곡이 적고 음색이 평탄하다.
- 바이닐 잡음은 음악과 따로 나오므로 재생 상태, 볼륨, 음소거, 원음 듣기를 코드로 따라가야 한다.
- 저역 위상 보정은 소니 기능의 모방이다. 실제 알고리즘은 비공개다.
- 고역 복원은 재생 중인 소리의 장기 평균에서 절벽을 찾아 잘린 지점을 정한다. 코덱이나 비트레이트를 믿지 않으므로 가짜 FLAC도 잡고, 절벽이 없는 곡의 출력은 원음과 비트까지 같다.
- 채우는 방식은 HE-AAC의 SBR처럼 잘린 지점 아래 대역을 위로 옮긴다. MP3로 압축한 곡을 압축 전 원본과 비교하니 왜곡으로 배음을 만드는 쪽보다 시간 변화가 훨씬 잘 맞았다. 없어진 정보를 되살리는 게 아니라 추정이다.
- 잘린 지점은 판단이 흔들리면 고역이 켜졌다 꺼졌다 한다. 찾을 때는 20dB, 유지할 때는 10dB로 기준을 나눈다.
- 원음 듣기는 전체 처리를 건너뛰고, 잠깐 비교하는 값이라 저장하지 않는다.
- 설정은 곡이 바뀌어도 유지되는 앱 전체 값이다.
- 샘플레이트 변환은 브라우저 내부에서 일어나서 끼어들 자리가 없다. soxr이나 r8brain을 쓰려면 재생 엔진을 바꿔야 한다.

## 재생목록

- 곡 id는 폴더를 다시 추가하면 바뀐다. 재생목록은 폴더 이름, 경로, 제목, 아티스트, 앨범으로 곡을 가리킨다.
- 경로로 먼저 찾고, 파일을 옮겼으면 태그로 찾는다. 못 찾은 곡은 지우지 않고 개수만 표시한다.
- 그래서 폴더를 제거했다가 다시 추가해도, 다른 PC에서 가져와도 곡을 다시 찾는다.

## Poweramp처럼 오디오를 직접 출력할 수 있나

웹에서는 안 된다. 휴대폰과 데스크톱 모두 같다 (2026-11-05 확인).

- Poweramp의 USB Exclusive와 UAPP는 자체 USB 오디오 드라이버로 OS 오디오를 건너뛴다. 웹페이지의 소리는 항상 OS 믹서를 거친다.
- 웹에서 유일한 우회로는 WebUSB로 드라이버를 만드는 것인데, 스펙이 오디오 클래스(`0x01`)를 보호 대상으로 막는다.
- Isolated Web App의 `usb-unrestricted`는 설치형 데스크톱 앱 전용이라 github.io에서 쓸 수 없다.
- 직접 출력이 필요해지면 네이티브 앱으로 감싸고 오디오 부분을 새로 만들어야 한다.

| 항목 | 웹에서 |
|---|---|
| 음원 kbps, 샘플레이트, 비트 수, 코덱 | 가능. `music-metadata`의 `format`, 휴대폰/데스크톱 동일 |
| 출력 샘플레이트 | `AudioContext.sampleRate`까지만. 장치로 그대로 나간다는 보장은 없음 |
| 출력 장치 이름 | 마이크 권한을 받아야 보임. 권한 없으면 이름이 빈 값 |
| 블루투스/USB 구분 | 전용 API 없음. 장치 이름으로 추측만 가능 |
| 블루투스 코덱, 전송 kbps | 불가능 |

음악 앱이 마이크 권한을 요청하는 것은 어색하므로 기본으로는 쓰지 않고, 파일 포맷과 출력 샘플레이트만 표시한다.

## github.io에서 파일/폴더를 읽을 수 있나

된다. github.io는 정적 파일만 내려주고 파일 읽기는 브라우저에서 처리한다. 사용자가 직접 고른 파일/폴더만 읽을 수 있고, 경로 지정 접근은 불가능하다.

| 방식 | 할 수 있는 것 | 브라우저 | 재방문 시 |
|---|---|---|---|
| 드래그 앤 드롭 (`dataTransfer`) | 파일, `webkitGetAsEntry()`로 폴더도 가능 | 전부 | 다시 끌어와야 함 |
| `<input type="file" webkitdirectory>` | 폴더 선택, 하위 파일까지 읽기 | 전부 (데스크톱 기준) | 다시 선택해야 함 |
| `showDirectoryPicker()` | 폴더 핸들로 읽기/쓰기 | Chrome/Edge 계열만 (Android Chrome은 132부터, Galaxy S22에서 동작 확인) | 핸들 저장 후 권한 확인만으로 재접근 |
| OPFS | 브라우저 전용 저장소에 파일 복사 | 전부 | 유지됨 (용량 차지) |

- 재생: `URL.createObjectURL(file)`을 `<audio>`에 연결
- 태그/앨범아트: `music-metadata` 같은 라이브러리로 브라우저에서 읽기
- 파일이 서버로 올라가지 않으므로 백엔드 불필요

### GitHub Pages 주의점

- 응답 헤더를 직접 설정할 수 없다. `SharedArrayBuffer`가 필요한 기능(멀티스레드 ffmpeg.wasm 등)은 우회가 필요하다. 일반 재생과는 무관하다.
- `hawakiki.github.io/저장소이름` 형태의 페이지들은 같은 origin이라 IndexedDB와 OPFS를 공유한다. 키/DB 이름이 다른 페이지와 겹치지 않게 접두어를 쓴다.

## 브라우저 저장소는 얼마나 유지되나

쿠키만 기간이 있고 나머지는 만료가 없어 반영구급이다.

| 저장소 | 저장 기간 | 용량 |
|---|---|---|
| 쿠키 | 지정한 만료일까지 (Chrome 최대 400일, Safari는 JS로 만든 쿠키 최대 7일) | 약 4KB |
| localStorage | 만료 없음 | 약 5MB |
| IndexedDB | 만료 없음 | 디스크의 상당 부분 (브라우저마다 다름) |
| OPFS | 만료 없음 | IndexedDB와 같은 할당량 공유 |

만료가 없어도 지워지는 경우:

- 사용자가 사이트 데이터나 인터넷 사용 기록을 삭제할 때
- 디스크 부족으로 브라우저가 오래 안 쓴 사이트부터 정리할 때 (`persist()` 승인 시 제외)
- 시크릿 모드를 닫을 때
- Safari에서 7일간 방문이 없을 때 (홈 화면에 설치한 웹앱은 예외)

음악 파일은 사용자 폴더에 그대로 있고 DB에는 참조만 들어간다. DB가 날아가도 폴더를 다시 고르면 복구되지만, 재생목록은 복구가 안 되므로 JSON 내보내기를 둔다.

## 지정한 폴더를 기억하고 자동으로 다시 연결할 수 있나

가능하다. 다만 localStorage는 문자열만 저장되어 폴더 핸들을 넣을 수 없으므로 IndexedDB를 쓴다.

| 시점 | 사용자 동작 | 결과 |
|---|---|---|
| 첫 방문 | 폴더 선택 | 핸들을 IndexedDB에 저장 |
| 두 번째 방문 | "다시 연결" 버튼 클릭 | 권한 창에서 "방문할 때마다 허용" 선택 |
| 그 이후 | 없음 | 페이지만 열면 자동 연결 |

`requestPermission()`은 사용자 클릭 안에서만 동작하므로 두 번째 방문에는 클릭이 필요하다. 완전 자동은 "방문할 때마다 허용"을 고른 뒤부터다 (Chrome 122 이상).

```ts
for (const handle of savedHandles) {
  const state = await handle.queryPermission({ mode: 'read' })
  if (state === 'granted') connect(handle)  // 자동 연결
  else showReconnectButton(handle)          // 클릭 시 requestPermission()
}
```

처리할 예외:

- 폴더 이동/삭제: 접근 시 `NotFoundError`가 나므로 "연결 끊김"으로 표시하고 다시 고르게 한다.
- 권한 해제: 자동 연결이 되더라도 "다시 연결" 버튼은 남겨 둔다.
- 중복 폴더: `isSameEntry()`로 같은 폴더인지 확인한다.
- 겹치는 폴더: `resolve()`로 확인해서 이미 추가된 폴더의 안쪽이나 바깥쪽 폴더도 거부한다. 곡이 두 번 잡히는 것을 막기 위해서다.
- 드롭: `getAsFileSystemHandle()`이 실패하거나 멈추면 `webkitGetAsEntry()`로 읽고, 이때는 저장되지 않는 세션 폴더가 된다.

Firefox/Safari는 폴더 핸들이 없어 자동 재연결이 안 된다. 매번 다시 고르거나 곡을 OPFS로 복사해야 하는데, 이번 범위에서는 다시 고르는 쪽으로 간다.

## 표지 자리

기본은 앨범 표지이고, 다른 표시는 설정에서 고른다. 표지 자리에서만 보여 준다.

- VU 미터: 정류 평균을 재고 바늘은 300ms에 99%, 오버슈트 약 1%다. 눈금은 전압에 비례한다.
- 0 VU 기준 기본값은 -10 dBFS다. 흔한 -18로 두면 요즘 곡은 바늘이 눈금 끝에 붙는다. 시험곡 기준 69%, 42%의 시간이었다.
- 미터는 리미터 앞에서 읽는다. 뒤에서 읽으면 피크가 켜지지 않는다.
- 피크 기준은 +1 dBFS다. 요즘 곡은 샘플 사이 피크가 0을 분당 약 190번 넘어서, 0으로 두면 시험곡에서 92%, 54%의 시간 동안 켜져 있었다.
- 다음 후보 LP: 앨범 표지를 라벨로 쓰고 회전각은 재생 시간을 누적한다. `currentTime`으로 계산하면 탐색할 때 판이 튄다.
- 다음 후보 카세트: 길쭉해서 휴대폰에서는 세로로 길게 놓는다. 릴 크기는 감긴 면적을 보존하고, 테이프 속도가 일정하니 적게 감긴 릴이 더 빨리 돈다.
